Why This Bot Exists

Most fitness apps fail because they trap you in solitary confinement, charge subscription paywalls, and encourage vanity binging. Winter Arc was engineered for a completely different human reality.

The Solitary App Trap

Why Mainstream Habit Apps Fail

  • Solitary Isolation: Logging reps into a private phone screen provides zero tribal peer pressure or shared celebration. When discipline dips, silence allows you to quit unnoticed.
  • Subscription Bloat & Paywalls: Essential tracking, basic streaks, and simple charts are gated behind recurring monthly charges and manipulative gamification.
  • Vanity Binging & Cheating: Open-ended apps let users log 1,000 pushups in a day to spike their ego, burn out by week two, and abandon the challenge entirely.
  • Data Commodification: Your health logs, habits, and private routines are mined, tracked, and stored on third-party ad networks.
The Winter Arc Solution

Peer Accountability Inside Discord

  • Tribal Peer Pressure: The bot lives inside your private Discord community. Your friends and pack see every rep, every clean streak, and every missed day.
  • Anti-Cheat 500 Daily Point Ceiling: Rigorous point math. Max 100 points per discipline. Consistency over 90 consecutive days always triumphs over erratic binging.
  • Zero Friction & Sub-Second AI: No apps to download. Log reps in seconds with slash commands or plain English via Groq LLM parsing (/quick).
  • 100% Data Sovereignty: You own the bot, the code, and the SQLite database. Zero external trackers, zero recurring subscriptions, zero vendor lock-in.

Step 1

Fork & Clone Repository

Begin by creating your own fork on GitHub, then clone it to your local machine, VPS, or server:

bash — git clone 
# 1. Clone your forked repository
git clone https://github.com/YOUR_USERNAME/winter-arc-discord-bot.git

# 2. Enter repository directory
cd winter-arc-discord-bot
Step 2

Discord Developer Portal Setup

Create your application and retrieve credentials from Discord:

  1. Open the Discord Developer Portal and click New Application.
  2. Under the Bot tab, click Reset Token and copy your DISCORD_TOKEN.
  3. Under Privileged Gateway Intents, enable both:
    • Server Members Intent (Required for tracking enrolled pack members)
    • Message Content Intent (Required for command processing)
  4. Under OAuth2 → URL Generator, select scopes bot & applications.commands, grant Send Messages, Embed Links, Manage Roles, and invite the bot to your server.
Step 3

Configure Environment Variables (.env)

Copy the example template to create your production configuration file:

bash — cp .env.example .env 
cp .env.example .env

Fill in your configuration variables inside .env:

dotenv — .env 
# ==============================================================
# WINTER ARC BOT CONFIGURATION
# ==============================================================

# Required: Bot Token from Discord Developer Portal
DISCORD_TOKEN=your_bot_token_here

# Required for /nuke: SHA-256 hash of secret 2FA answer
NUKE_SECURITY_HASH=ae50ad81a2d4006e372c0bd3220f24c377345455d0e980c3f0d94f0e5faf2561

# Optional: Default server role & channel IDs (can also be set in-server via /admin)
WINTER_ARC_ROLE_ID=
WINTER_ARC_CHANNEL_ID=

# Optional: Google Gemini API Key for /grind deep work scoring (free at aistudio.google.com)
GEMINI_API_KEY=your_gemini_api_key_here

# Optional: Groq API Key for /quick natural language parsing & failover (free at console.groq.com)
GROQ_API_KEY=your_groq_api_key_here

# Optional: Groq inference model (defaults to llama-3.3-70b-versatile)
GROQ_MODEL=llama-3.3-70b-versatile
Step 4

Choose Your 24/7 Hosting Platform

Discord bots require a continuous Python process maintaining an active WebSocket gateway connection. Pick your preferred environment below:

Deploying on Wispbyte (or any Pterodactyl Panel)

Wispbyte provides low-cost 24/7 Discord bot server containers running Python with automatic crash recovery, web console monitoring, and integrated Git deployment. Select your preferred deployment method below:

1
Create a Python Server

In your Wispbyte dashboard, select Create Server and choose the Python / Generic Bot egg (Python 3.11+ recommended).

2
Configure GitHub Settings

Navigate to the GitHub Integration tab in your server sidebar and configure your repository fields:

  • Repository URL: Enter your GitHub repository (e.g. https://github.com/vishnunandan555/winter-arc-discord-bot)
  • Branch: main
  • Authentication: Leave blank for public repositories. (Only needed for private repos: enter your GitHub Username and a Personal Access Token with repo read scope).
  • Auto Update on Startup: Toggle ON to automatically pull new commits whenever your server boots or restarts.
3
Clone the Repository

Click the Clone / Pull button near the top of the GitHub page. Wispbyte will clone your repository directly into the server directory.

4
Configure Secrets (.env) in File Manager

Git purposely ignores secret files like .env and databases (*.db) for security. Go to File Manager in your panel, click New File, and save your credentials as .env:

dotenv — .env (File Manager) 
DISCORD_TOKEN=your_token_here
APPLICATION_ID=your_id_here
PREFIX=!

Database Safety: Live SQLite databases (winter_arc.db) are untracked by Git, so pulling new commits will never overwrite user streaks or data.

5
Verify Startup & Launch Bot

In the Startup tab, ensure Startup Command is set to python bot.py. Then navigate to Console and click Start. The container installs dependencies from requirements.txt automatically and boots 24/7.

1
Generate Production ZIP Bundle Locally

bash — python create_deploy_zip.py

Deploying with Docker & Docker Compose

Containerized deployment with persistent volume mounting ensures your SQLite database (winter_arc.db) is safely preserved across restarts.

dockerfile — 1. Dockerfile

WORKDIR /app
COPY requirements.txt .

COPY . .
CMD ["python", "bot.py"]
yaml — 2. docker-compose.yml 
version: '3.8'
services:
  winter-arc-bot:
    build: .
    container_name: winter_arc_bot
    restart: always

      - .env
    volumes:

System Architecture

Data Sovereignty & SQLite Design

Engineered with a clean Data Access Object (DAO) architecture. All calculations, streaks, and shields run locally on your server.

Local SQLite Storage

All member data, timestamps, volume counts, and streak milestones reside in a single local file: winter_arc.db. Backing up your entire server takes one command: cp winter_arc.db backup.db.

Zero Telemetry & Privacy

No analytics SDKs, no tracking pixels, and no external databases. The bot communicates solely with Discord's official Gateway and your optional LLM providers (Groq/Gemini).

Fault-Tolerant Scheduling

The scheduler runs an evaluation ticker loop every 30 seconds pinned to Asia/Kolkata (or your custom timezone in BOT_TIMEZONE). Even if restarted, bot state flags prevent duplicate broadcasts.

Frequently Asked Questions

Common Questions & Answers

Everything you need to know about the Winter Arc bot, scoring math, AI workout parsing, and self-hosting.

What is the Winter Arc Discord Bot? +

The Winter Arc Discord Bot is an open-source, self-hosted fitness and habit accountability ecosystem built with Python 3.11+, discord.py 2.x, and SQLite. It replaces solitary, subscription-heavy habit apps by moving daily discipline tracking directly into your private Discord community with your closest friends or training pack.

How does the anti-cheat 500 daily point ceiling work? +

To eliminate erratic vanity logging and stop users from burning out by logging 1,000 push-ups in a day, points are mathematically capped at 500 points per day across 5 core disciplines: Push-ups (100 pts), Pull-ups (100 pts), Squats (100 pts), Sit-ups (100 pts), and Running (100 pts). Reaching the top Apex rank requires stacking consistent volume across all 90 days rather than single-day binge workouts.

How do the Groq and Google Gemini AI integrations work? +

The bot features two built-in AI capabilities:

  • Groq AI (/quick [text]): Parses natural language workout summaries in milliseconds via llama-3.3-70b-versatile (e.g. "ran 5km and did 40 pushups") into structured discipline logs. If no API key is provided, an internal regex parser acts as an automatic fallback.
  • Google Gemini (/grind [text]): Evaluates custom physical workouts (Surya Namaskaras, gym, yoga) or cognitive deep work to award verified bonus points (+5 to +50 pts, capped at 1x per day; core disciplines excluded). Backed by an automated sub-second Groq fallback with geo-block circuit breaker to prevent downtime.
What is the Council Trial system and how does /accuse work? +

To maintain authentic standards and eliminate unearned fluff, Winter Arc includes a democratic community verification system:

  • Automated AI Sentinel: When a user logs buzzword bingo or ungrounded claims via /grind, Amarok credits token effort points (+10 pts) and immediately auto-summons the Council.
  • Peer Challenge (/accuse @member): Any enrolled warrior can challenge an unverified grind log. Before summoning the Council, an ephemeral modal enforces the Winter Arc Honor Code to prevent jealousy or petty rivalry.
  • Democratic 10-Minute Vote: Enrolled pack members vote live via interactive buttons ("🔨 Guilty" vs "🛡️ Innocent") with courtroom GIFs. If the accusation is confirmed guilty, points are stripped; otherwise, the log stands.
  • Admin Disciplinary Control: Administrators can run /admin grind block|unlock with custom durations and reasons to enforce pack standards.
What is the Streak Shield defense mechanism? +

Real life includes legitimate rest, travel, and illness. For every 7 consecutive active days (at least 30 points per day), members earn 1 Streak Shield (inventory capped at 3). Running /shield use [target] [reason] protects your streak during a recovery day without resetting your progress to zero.

Can I self-host this bot on Wispbyte, a Linux VPS, or Docker? +

Yes. Winter Arc is engineered specifically for turnkey self-hosting:

  • Wispbyte / Pterodactyl: Direct GitHub repo pulling with auto-update on restart, or upload a pre-packaged bot_deploy.zip bundle.
  • Linux VPS (Systemd): Run on Ubuntu/Debian using the included production systemd service definition.
  • Docker: Run docker compose up -d with the included Dockerfile and docker-compose.yml for persistent SQLite storage.
  • Render / Railway: Deploy as a continuous Background Worker process.
Is the Winter Arc Discord Bot completely free and open-source? +

Yes, 100% free under the permissive MIT License. There are zero subscription paywalls, no paid tiers, and no advertisements. You maintain full data sovereignty over your private SQLite database (winter_arc.db).

How do I enroll members and configure the bot in Discord? +

Once online, an administrator runs /admin set_channel channel:#winter-arc to isolate all automated daily broadcasts into one dedicated channel, and /admin set_role role:@Winter Arc to set the notification role. Members then simply type /enroll to join the pack and begin logging workouts.
